# Extalia v0.4.157 — Desktop and npm/Web beta

This beta brings the accumulated Native, knowledge, connection and shared office
updates into one Desktop/Web release. It remains in the v0.4 milestone; the
production v0.5 scanner/Python and complete permission/ownership gates are not
declared complete.

## Install or update

The npm application includes the Web client, local Bridge and matching platform
daemon. Install the application rather than a daemon package alone:

```bash
npm install -g extalia-vo@latest
extalia
```

Requires Node.js 22.13+ on the 22.x line, or 23.4+ on newer lines. Contributors
continue using pnpm in the source checkout. Test npm installs in an isolated
prefix, not inside the pnpm-linked project.

Desktop installers are provided for macOS Apple Silicon/Intel, Windows x64 and
Linux x64. The standalone Web ZIP contains the client; agent execution still
needs the local Bridge or Desktop host. All release files have entries in
`SHA256SUMS.txt`.

macOS builds are free **ad-hoc signed previews**, not Apple-notarized apps. They
can show an unidentified-developer warning. If you trust the official download,
use System Settings → Privacy & Security → Open Anyway after the first launch
attempt. Preview Mac builds use manual downloads for updates. Strict app/archive
signature checks remain required; no installer disables Gatekeeper.

## Native control and teams

- Durable original planned-task records and planning-lifetime receipts preserve
  unresolved execution evidence across restart. They do not prove that remote
  processes, child work or writers have safely stopped.
- Recovery inspection, action-intent records, lease/reaper and isolation
  foundations retain fail-closed admission behavior. Full effect-time authority,
  physical settlement and automatic recovery closure remain later gates.
- Progressive workspace memory uses a bounded catalog, literal search and paged
  reads; workers retain read-only recall. Built-in recall and opt-in concise
  response guidance do not install Claude-Mem or Caveman.

## Skills and knowledge

- External skill metadata and every skill read require current registry scanner
  evidence. Legacy consent records review only; canonical built-ins cannot be
  overridden by an external name/source flag.
- Choose **Learn as skill** for a Native message, or start with `/learn-skill`,
  to propose one generated candidate with host-bound provenance into the user's
  Skills library. Existing write approval policy applies; no worker, approval or
  activation permission is inferred from the prompt.
- **Production SkillSpector remains unavailable.** Imported/generated candidates
  remain quarantined. Inspection records may report scanner-unavailable; they are
  not clean-scan claims. The generated package is what is inspected, not a
  certification of the original URL or every referenced file.
- Skills dependency/category/intent routing previews are read-only diagnostics,
  never dispatch authority. Mission-worker skill parity remains open.
- The bounded Obsidian-compatible 3D graph includes folder/kind/tag/time and
  neighbourhood filters with consistent search, counts and selected-note views.
  These do not grant whole-vault model access or complete cross-agent ACLs.

## Connections, messages and shared UI

- Hardened connector transactions and observation lifecycle handling distinguish
  unavailable sources from working agents. External configuration changes still
  require preview, approval, backup and undo; startup performs no silent injection.
- Shared Chat, Observe and character-dialog messages render richer links,
  attachments, questions, approvals and task results while retaining inert source
  data. Opening a character directly preserves the user's camera framing; board
  shortcuts locate the character.
- Per-message learning choices and uploaded files survive a failed first-session
  handoff without letting stale navigation select or overwrite a newer draft.

## Office assets and distribution limits

The shared public inventory contains **106 registered GLBs**, totaling
**691,568,420 bytes (about 660 MiB)** before archive compression. Garment and
wardrobe models account for most of this increase; download and first-use asset
loading can take time. A successful build is not a measured FPS guarantee.

Models retain individual MIT, RenderHub, CC-BY, non-commercial CC and Sketchfab
licenses. Five vehicle models have non-commercial restrictions. The commercial
switch changes runtime selection but does not omit those files from packages.
Source code's MIT license does not relicense the models. See the complete
[asset notices](../../apps/web/public-assets/THIRD_PARTY_NOTICES.md) before reuse.
Private source archives, local visual-review entries and Python bytecode are
excluded from the release checkout.

The Rust store migrates through **schema 12**. Older binaries refuse newer store
schemas; keep a profile backup before attempting a downgrade. Desktop and Bridge
share the same profile directory. No release action changes another agent app's
configuration or rewrites a real user profile.

Production embedded Python, pinned scanner artifacts/report normalization,
supervised worker sandboxing and complete workspace/agent ACL remain open in
[#54](https://github.com/Extalia-VO/extalia-virtual-agent/issues/54) and the
[PRD tracker](../product/prd-app-flow-and-live-agents.md#11-status-tracker).
