# ADR 0030: Authoritative Native mission recovery inspection

Status: Accepted for implementation, 2026-10-27

## Context

Native gate 3.3 precedes executor approvals and category skill routing. Rust owns
mission transitions, events and leases, but the host retains a separate display
checkpoint. A crash between a Rust terminal commit and the host checkpoint can
leave that display permanently recovering. Startup recovery also represents
genuinely uncertain execution; these cases must remain distinct.

## Decision

Add the profile-scoped, read-only `mission.snapshot` daemon operation. One SQLite
read transaction returns canonical mission identity, version, journal sequence,
task states/attempts/assignees and leases with their recorded acquisition and
expiry times. Validate row/payload consistency and the current scoped graph, and
bound the response using the existing mission limits. The current Rust schema
does not retain immutable original graph membership; the host must additionally
require exact task membership against its retained original run before accepting
a terminal projection repair. No heartbeat time is invented.

Persist new mission authority explicitly: TypeScript, or Rust with its profile
and canonical workspace identity. Historical records without authority remain
unknown; changing the current backend setting cannot establish ownership.

The host exposes recovery refresh through the existing managed mission API and
Missions UI. It validates stored identity against the authoritative snapshot and
shows canonical states even when the operational run must remain quarantined.
Refresh is serialized per mission and rechecks local activity after awaiting the
daemon. Unavailable authority, a mismatch or a failed checkpoint write stays
recovering; there is no fallback to a different authority.

Only a projection whose uncertainty was generated by host restart may adopt an
already-terminal Rust state, and only when the canonical mission and every task
are terminal, there are no leases, and no local execution or reservation remains.
Pre-existing execution uncertainty or persistence failure is never cleared by
this operation. Persist recovery provenance so an old or ambiguous checkpoint
cannot accidentally satisfy that exception.

Missing answers, token usage and evidence remain unavailable or unverified.
Refresh does not fabricate results, replay providers/tools, retry work, change
Rust state or release/integrate/delete worktrees.

## Consequences and verification

This completes a bounded inspection/projection slice, not all of gate 3.3.
Independent heartbeat, live reaping/fencing, explicit closure of uncertain work
and executor action approvals remain separate gates. Absence of a host promise
alone does not prove physical settlement.

Tests must cover profile/session/task/assignee identity, old unknown authority,
active execution, unknown/queued/in-flight tasks, leases, daemon failure,
checkpoint failure and restart after an acknowledged terminal projection update.
The terminal shadow case must preserve completed results that actually exist and
leave missing output absent. Temporary profiles and scripted providers suffice.
